# Project Plan

## Working approach

Each portfolio will be handled in small steps:

1. Read the portfolio requirements and list the evidence needed.
2. Build the smallest useful example that meets the requirements.
3. Run the SQL or database commands.
4. Check the results and fix any issues.
5. Save evidence and explain what the results mean.
6. Update the portfolio README.
7. Commit the finished piece of work.

## Planned work

| Portfolio | Planned work |
|---|---|
| 1. Design and modelling | ER diagram, table design, keys, constraints, and normalisation |
| 2. Query optimisation | Useful SQL queries, query plans, indexes, and a comparison |
| 3. Transactions and concurrency | Order transaction, rollback test, and two-session stock test |
| 4. NoSQL | MongoDB customer order-history documents and queries |
| 5. Distributed databases | Primary/read-replica design, data flow, and trade-offs |
| Final documentation | Evidence, reflection, references, and AI-use declaration |

## Commit approach

Commits will be made when a useful piece of work is ready. Commit messages will say what changed, for example:

- `docs: add ShopFlow case study`
- `feat: create relational schema`
- `test: check order rollback`

The commit history will show the real order of the work. Commits will not be backdated or created just to reach a target number.
